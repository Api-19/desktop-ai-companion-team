# CPED F/S/G 试标指南 v1.0

版本：`rcpem-public-pilot-v1.0`；日期：2026-10-18；任务：[Issue #3](https://github.com/Api-19/desktop-ai-companion-team/issues/3)。

状态：负责人授权后确定的首轮试标规范，可据此准备材料和独立试标；尚未经过双人一致性检验，不是正式研究验收标准。替代 Issue 原先“只标第一个有内容的动作”的 S 规则。已有 50 条材料草案保留，只需按本指南校对和补字段，不重新抽样凑数。

## 1. 方法选择与依据

采用 **功能片段上的动作集合 + 片段顺序 + 独立互动特征**。分类对象是可见回复的交际功能，不是人格、隐藏动机或“正确回应”。同一语境可以有多种合理策略，历史实际回复只提供一种观察。

- [DIT++ / ISO 对话行为说明](https://dit.uvt.nl/)支持区分交际功能与其他维度，并允许话语具有多种功能。本指南借用结构原则，不声称实现 ISO 全集或标准兼容。
- [Welivita & Pu, COLING 2020](https://aclanthology.org/2020.coling-main.429/)区分追问、认可、建议、分享经历等共情回应意图，并在回复内部按句标注。其共情语料有领域限制，不直接整套移植。
- [Liu et al., ACL 2021 / ESConv](https://aclanthology.org/2021.acl-long.269/)区分提问、复述、反映感受、自我披露、宽慰、建议、信息等支持策略。只作为支持场景的定义参考，不把所有日常聊天都改成情绪支持。
- [Sharma et al., EMNLP 2020 / EPITOME](https://aclanthology.org/2020.emnlp-main.425/)分别标记共情机制并提供文本依据，启发本指南记录证据而不只给整轮单标签。
- [Bai et al., 2025 预印本](https://arxiv.org/abs/2505.15316)研究一轮中的连续多策略，支持保留动作序列；其情绪支持实验不等于本项目个人模仿效果证明。

以下 12 个具体动作和四个互动特征是本项目的试标设计，尚无证据表明这是唯一或最优分类。暂不训练新模型、不改变线上策略或旧标注页面。

## 2. 材料、上下文与信息单元

### 2.1 一个事件是什么

一个事件是“可见前文 + 最后一个非目标说话人的话轮 → 目标说话人的完整下一话轮”。完整下一话轮包含同一人连续发送、直到下一人发言前的所有消息，保留消息边界与顺序。一次接话算一个事件，不把同轮拆成几条独立样本。

只取官方 train。使用来源 dialogue ID、原始行/utterance ID、角色 ID（带剧集命名空间）、源版本和抽样记录定位。正文不贴进 issue，记录来源划分。CPED 原 DA 保留在整理元数据里，不展示给独立标注 A/B，也不预填项目标签。

上下文从同一原始对话取目标话轮前最近最多 6 个完整话轮，必须含紧邻的对方话轮；不足 6 个取全部。一个话轮内的连续消息不截断。不跨对话补上下文，不看目标之后的发言。6 是本轮可复现的工作参数，不是文献结论。超长或缺失到无法理解的材料标记排除/待修复，记录原因；不能默默换成不同窗口。

记录 `context_truncated`、`missing_context`。有截断但当前问题仍可判断的样本可留；指代/角色/问题依赖缺失内容时用 `insufficient_context`。修复材料时先给两人同一新版本，保留原版本和修订理由。

### 2.2 F 信息单元与 S 功能片段分开

- **F 信息单元**：将上下文中可独立承接的事实、问题、感受、请求等划为有 ID 的单元。保留否定、时间、条件、施事和更正；不要按逗号机械切分。
- “明天要汇报，我有点紧张”可分成“明天要汇报”和“对此紧张”；“不是明天，是周五”整体保留为一个更正单元。
- 单元由整理者在不看目标回复的条件下提出；如果已经看过，记录暴露状态，由未看目标的人复核。进入试标前统一单元版本。A/B 可以另提切分异议，不各用一套单元 ID。
- **S 功能片段**：对目标回复划分最小但足以判断交际功能的文本。可短于一句或跨连续消息；跨消息时保存多个 span，不拼改原文。不同动作能分开就分开；不可分的多功能片段允许多个动作，不能硬造先后。
- F 和 S 的单元集合、编号分开，禁止拿目标回复反推“上下文唯一正确切法”。

## 3. S 的 12 个动作

通常每个功能片段一个动作；无法分割且同时满足两个明确定义时可以多选，并写理由。若只是两种解释之间拿不准，用 `uncertain` 加候选，而不是多选。所有下列例子均为独立编造。

| 代码 | 名称与纳入条件 | 正例 | 边界 / 排除 |
| --- | --- | --- | --- |
| ACK | 接收/理解反馈：表示听见、收到、理解，不额外回答事实或作出行动承诺 | 对方叙述后说“原来如此” | 对“你明天来吗”回答“嗯”是 INFORM；对“明天帮我带书”说“好”是 COMMIT；不能仅凭词形判 ACK |
| INFORM | 回答/告知/解释：给出事实、经历、状态或原因，也含纠正事实 | “会议改到周五了”“我今天在实验室” | 个人经历仍属 INFORM，再加 self_disclosure；建议做什么不是 INFORM |
| ASK | 询问/澄清：确实希望对方提供或核实信息 | “你指的是哪份报告？” | 反问若表达评价或否定，标 EVALUATE；“能帮我拿一下吗”在索取行动，标 REQUEST |
| EVALUATE | 评价/立场：赞成、反对、判断好坏或表达偏好 | “这个安排不太合理”“你这次做得真好” | 拒绝具体请求用 REFUSE；认可对方感受的可理解性用 VALIDATE；单纯纠正日期用 INFORM |
| VALIDATE | 理解/认可体验：复述要点以核对理解，或明确承认对方感受和经历 | “所以你担心的是来不及？”“准备这么久还遇到变更，难怪会烦” | 真正询问未知原因用 ASK；“原来如此”仅反馈用 ACK；不从“嗯嗯”推断深层理解 |
| SUPPORT | 安慰/鼓励/宽慰：表达关切、陪伴或信心，以支持对方 | “辛苦了，先歇一会也没关系”“别灰心，可以慢慢来” | 具体下一步方案用 SUGGEST；要求对方来安慰自己不是 SUPPORT |
| SUGGEST | 建议/劝告：提出有助于对方的做法，包括叮嘱提醒 | “可以先问问负责人”“记得带伞” | 为完成说话者需求而要求对方行动用 REQUEST；不按祈使句/问句形式机械区分 |
| REQUEST | 请求/邀请：要求对方采取行动、给予资源/注意，或邀请共同活动 | “帮我看一下这页吧”“今晚一起吃饭吗？” | 真正索取事实用 ASK；明确为对方解决问题的做法用 SUGGEST；兼具两者且不可分可多标并说明 |
| COMMIT | 承诺/提供帮助：承担未来行动，或明确提出自己可提供的帮助 | “我明天帮你取”“要不我替你问一下？” | 单纯能力/日程陈述用 INFORM；仅建议对方自己行动用 SUGGEST；需记 `subtype` 为 promise 或 offer |
| REFUSE | 拒绝/设边界：拒绝请求、邀请或互动，要求停止越界行为 | “今晚不能去”“这件事我不想聊” | 不同意某个观点用 EVALUATE；“今天没去”只报告既往事实用 INFORM |
| SOCIAL | 社交/对话管理：问候、感谢、道歉、告别、明确开闭话题 | “谢谢你”“先聊到这吧” | 有实际内容的安慰不因礼貌而全部标 SOCIAL；另记 subtype，如 thank / apologize / greet / close / topic_shift |
| OTHER | 可识别但以上未覆盖的功能 | 如材料出现未覆盖功能，描述它做了什么 | 不等于看不懂。必须写功能描述，积累后决定是否增类 |

**不可判断是状态，不是第 13 个动作。** `status` 为 `judged / uncertain / insufficient_context`。后两种必须写原因；`uncertain` 可记候选动作，`insufficient_context` 不强行猜。`OTHER` 则属于 `judged`，必须有明确功能描述。

## 4. 四个可并存的互动特征

每个已判断片段分别记录 `present / absent / unclear`，不是从动作自动推导。不打强度分，不推断人物关系。`present` 和 `unclear` 都写局部证据/原因；片段本身不可判断时特征可留 null，表示未评。

| 字段 | 何时 present | 边界 |
| --- | --- | --- |
| humor | 可见的玩笑、夸张、调侃、搞怪表达 | 不预设是善意、亲密或有效；严肃辱骂不因冒犯而自动算幽默；仅文字无法分辨就 unclear |
| affection | 明确表达喜欢、想念、亲昵称呼等 | 不凭已知情侣/朋友身份补标签，也不推断关系阶段 |
| seek_care | 明确索取陪伴、关注或安慰 | “陪我一会儿吧”可标 REQUEST + seek_care；“我难受”只是陈述，不能自动推出求哄 |
| self_disclosure | 提供说话者自己的经历、状态、感受或偏好 | “我以前也遇到过”是 INFORM + self_disclosure；“我觉得你可以问问”里的“我觉得”不是自动自我披露 |

因此不再把“调侃”和“撒娇”当成与问答、建议互斥的主类；幽默可修饰多个动作，亲昵表达、求关注和自我披露分开记。旧 A–E 结果保留旧版本，不自动迁移。

## 5. 边界练习（公开教学例，不作未见测验）

| 可见语境 → 回复 | 示范标法与理由 |
| --- | --- |
| “我又迟到了。”→“你这是和闹钟有仇吧。” | EVALUATE + humor；不是索取真实信息，不因问句形式标 ASK |
| “我准备放弃。”→“你是担心时间不够，还是不喜欢这个方向？” | ASK；提出备选原因请求核实，不直接宣称理解成立 |
| “我担心时间不够。”→“所以主要卡在时间，对吗？” | VALIDATE；复述已有要点并核对理解，不是问新事实 |
| “今天好累。”→“我也是。” | INFORM + self_disclosure；可表达共同体验，但没有充分证据就不自动补 SUPPORT |
| “今天好累。”→“辛苦了。要不要先睡会儿？” | 两段 SUPPORT → SUGGEST；后句主要建议休息，不是调查是否困倦 |
| “今晚一起吃饭吗？”→“好呀。” | COMMIT，promise；实际接受并承担共同行动，不是 ACK |
| “这个方案最省钱。”→“我不同意，这个还没算运费。” | EVALUATE → INFORM；反对观点并给出事实依据 |
| “帮我写完这份报告。”→“这部分需要你自己完成。” | REFUSE；此处在拒绝请求，不只按句式标建议 |
| “能陪我一会儿吗？” | 有相应语境时 REQUEST + seek_care；不因为撒娇口气而覆盖请求功能 |
| “我以前也卡在这里，确实很折磨。可以先把问题拆小。” | INFORM(self_disclosure) → VALIDATE → SUGGEST；保留整轮顺序 |
| “你先忙。”→“那我可要收陪聊费啦。” | 上下文足以认定玩笑时可为 REQUEST + humor；无法判断是真要求还是玩笑时 uncertain，记录候选与疑点 |
| 只有“[某表情]”，无可见图像或稳定释义 | insufficient_context；不能凭猜测生成表情含义 |

旧的“开头嗯嗯一律跳过”取消：ACK 如实际出现则保留。若只做首动作基线，必须另行派生并说明规则，不覆盖完整标注。

## 6. F 和 G 的执行规则

### F：可接受焦点与实际焦点分开

1. **先锁定第一步**：A/B 只看同版上下文与 F 单元，选可接受单元集合。`preferred` 为某个已选单元、`no_unique` 或 `insufficient_context`。允许选多个；整体承接时选择被整体承接的单元集合，并记 `mode=holistic`。第一步结果封存后才能看回复。
2. **第二步**：揭示完整目标回复，记录实际承接的单元及首次承接顺序。能映射时填单元 ID；同时承接可并列，不硬排。没有承接任何已列单元时记录 `no_match`，上下文不足则记录 `insufficient_context`，两者不同。
3. 不回改第一步以迎合真实回复。材料整理者若已看过回复，不能把自己的 F 第一步结果算作盲标；每名标注者记录 `reply_seen_before_step1`，已暴露记录只作为开放复核。
4. 单元有缺漏时提异议，先保存当次原答案。调整单元后，对受影响事件按新版本重标，分别报告原始一致性与修订结果。

### G：只在有合规候选时做

G 以“一个事件 × 一个候选历史片段”为一对，候选按使用方式定义为**可借鉴的回应方式/措辞素材，不是当前事实来源**。候选限目标说话人在同一原始对话内、目标话轮之前的已有发言及其必要前文；先不跨剧集/角色拼历史。材料不足就记 `not_applicable`，不能编造真实历史凑数。

- `applicable`：在当前信息下可借鉴，未发现焦点、语气或事实/角色使用冲突；无需也不得原样照抄历史事实。
- `not_applicable`：存在可指出的冲突、明显不相关或只能靠捏造事实才能使用。
- `uncertain`：当前语境或候选缺失到不能判断。

记录简短理由和证据。人工 G 只看上下文与候选，不看当前目标回复；应在 F 第一步之后、揭示回复之前完成。已看过目标回复者记录暴露，结果另报。每个事件实际有几个候选就报几个，不将事件数当配对数。无候选用事件级 `g_status=not_applicable` 和空列表，不算 uncertain。

## 7. 首轮流程与交付

1. 整理者先按本指南核对现有 50 条：来源/权利条件、同版窗口、目标话轮边界、F 单元、无未来信息、无重复。未核实项列出，不默认通过。不给 A/B 预填 DA、模型建议或教学答案。
2. A/B 用本指南独立编造例子练习，讨论规则；教学例不计入 50 条独立一致性。
3. 从这 50 条中按固定顺序先做 10 条同版小批，A/B 不互看答案：先 F1 与 G，再锁定，再 F2 与 S。完成后保存两份原始结果并讨论分歧。
4. 若定义不变，剩余 40 条沿用 v1.0；若改定义，发布新小版本并对已标且受影响部分两人重新独立标，不把跨版本结果混算。更改规则后看过的材料不再声称未见。
5. 汇总后才做后续 200 条；本指南不自动授权扩样、付费模型调用或新数据来源。200 条继续沿用 Issue 要求至少 20% 双人独立复标。

本轮使用 **独立 JSON 记录文件**，按下方格式手工填写即可；现有 Admin 单标签策略页与 `m1_labeler.py` 的 A–E 假设不能完整承载本协议，**不要把 12 类硬塞旧页面或旧模型脚本**。现有 F 页面可参考交互逻辑，但并列焦点/暴露记录等字段以本协议为准。无需重写保存/撤销等已有功能；如后续要集成页面，另立实现契约。

每人独立交付一个 JSON，禁止使用同一路径覆盖他人结果；不要通过共享答案实现“独立双标”。schema/格式例见 [annotation_record.example.json](annotation_record.example.json)。该文件是独立编造的教学记录，包含示范答案，不能混入盲标材料包。

文件顶层固定：`protocol_version`、`material_version`、`annotator_id`、`phase`、`records`。匿名标注者 ID 即可。`phase` 为 `training / pilot / adjudication`。每个事件保留来源定位与文本版本哈希（在获准的任务包 manifest 中），正文材料与结果按获准方式单独交付，不上传真实 CPED 原文或完整标注包到代码仓库。

S 片段的 `spans` 使用 `message_id / start / end / text`；偏移按原消息 Unicode 码点、0 起始、左闭右开，不按字节或 UTF-16；`text` 必须等于该切片，保持原文。`segments` 数组按出现顺序，`actions` 数组内部无先后。未判断片段 `actions=[]`，`candidates` 另存候选。`reason` 在 uncertain、insufficient_context、OTHER、多功能同片段时必填。

原始 A/B、AI 建议（如以后获准使用）、裁决结果三个版本分开存。裁决不能改写原始一致性；保留争议、改动、理由、裁决者与版本。任务包哈希、指南版本和来源版本必须可追溯。公共仓库只交规范、合成示例和不含正文的来源/切分清单。

## 8. 怎样判断试标是否可用

首轮是规范检验，不设伪精确的“达到某分数即可上线”。至少交付：

- 50 个事件的分母、排除/缺失/已暴露数量，F/S/G 分别有多少有效判断；未补齐 50 时明确报实际数。
- F 第一步：可接受集合的逐事件 Jaccard、首选一致率，`no_unique` 与不足单独报；两空集合不当作满分，单列数量。F 第二步：承接集合重叠与顺序差异，单列 no_match。
- S：先报告独立切分边界的 precision/recall/F1（按 message ID 与码点位置，忽略消息两端边界），再在边界完全相同的片段上报告动作集合完全一致率、逐类差异与支持数；对齐片段分母必须同时报告，不能只展示容易对齐的子集。另报每个事件动作集合 Jaccard 与动作序列的归一化编辑距离，序列每个位置是排序后的动作集合。
- 四个互动特征分别报告状态一致率；有足够类别变化时可补 Cohen's κ，只有单一类别时记不可计算，不报虚假满分。不可判断数量、OTHER 原因独立列出。
- G：实际事件×候选数、三类分布与一致率；not_applicable 不进入配对分母。候选未准备时明确 G 未实施，不妨碍单独报告 F/S 试标。
- 分歧至少按“上下文不足、切分不同、定义重叠、特征证据不足、漏类”归因。针对高频问题修订指南，再决定是否扩样；不以两人讨论后一致冒充独立一致。

个人策略研究后续需比较**相似语境下的动作选择、组合、顺序和互动特征**。本批跨角色试标验证标注可行性，不能证明已学会某个人，不能把“更合适/更会安慰”自动当成“更像本人”。不收集私人聊天、个人习惯卡、关系推断或主人的私有评分。

## 9. 记录字段速查

| 字段 | 必填内容 / 约束 |
| --- | --- |
| record.event_id / material_ref | 指向同一冻结任务包的事件 ID 和 manifest；训练示例可额外内嵌 training_material，正式输出不复制正文 |
| f_step1 | locked、reply_seen_before_step1、status、acceptable、preferred、mode、reason；status 为 judged 或 insufficient_context；不足时 acceptable=[]、preferred=insufficient_context；无唯一首选不等于不足 |
| f_step2 | status、mode、responded_groups、reason；status 为 judged / no_match / insufficient_context；responded_groups 按首次承接顺序存 ID 数组，同一组表示同时承接；重复承接只记录第一次；无匹配/不足时为空 |
| F mode | units 或 holistic；holistic 仍列出所承接的 ID，整段笼统回应无法定位时说明原因，不能强迫所有单元都算命中 |
| g_status | annotated 或 not_applicable；前者至少有一个 g_pair，后者列表为空，另填 g_reason 说明未准备候选或历史不足的原因 |
| g_reply_seen_before_judgment | 是否在判断 G 前已经看过目标回复；未做 G 时为 false |
| g_pairs[] | candidate_id、label、reason、evidence；label 只取 applicable / not_applicable / uncertain；evidence 为可定位的上下文/候选消息 ID，不依赖当前真实回复 |
| s.segments[] | id、spans、status、actions、candidates、subtype、modifiers、reason；按原文出现次序列出，标点不独立成段；不遗漏开头 ACK 或结尾 SOCIAL |
| subtype | COMMIT 必填 promise / offer；SOCIAL 必填 greet / thank / apologize / close / topic_shift / other；其余为 null；同片段多动作需 subtype 时，用动作代码为键的对象分别存 |
| modifiers | humor / affection / seek_care / self_disclosure 四键，每键为 value 与 evidence；value 取 present / absent / unclear，未评时为 null |
| unit_objections | 单元异议数组；无异议为 []，有异议写 unit_id、problem、proposal，不直接改冻结材料 |

本轮不为“能填进旧页面”缩减标签，不要求开发新软件。格式/文档与人工一致性是不同验收项；格式通过不代表标注正确或效果成立。
